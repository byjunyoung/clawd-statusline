# 성장 설계 (0.3.0)

쓴 토큰으로 레벨을 매기고 사용 습관을 다섯 스탯으로 보여준다. **카드 하나가 전부다.**
상태줄은 0.2.0과 바이트 단위로 같다.

작성 2026-09-04.

## 0. 무엇을 버렸나

세 번 버렸다.

**Clawd 옆에 세울 새 생물**을 세 번 그렸고 세 번 다 실패했다(1절).
그다음 **Clawd에게 악세사리를 입히는** 것을 만들어 돌려보고 뺐다. 9칸짜리 스프라이트에
얹을 수 있는 건 머리 위 작은 색덩어리뿐이고, 65레벨에 모자 7개면 한참 올려야 하나 열린다.
보상 밀도가 낮은데 보상 자체도 약했다. 촘촘하게 고쳐도 천장이 캔버스라 근본이 안 바뀐다.

세 번째는 **원본에 없던 표정**이다. 시즌 1이 잔량에 따라 입을 벌리고 눈을 감는 포즈 다섯을
새로 그려 쓰고 있었는데, 그것부터가 짝퉁으로 보이는 원인이었다. 앤트로픽 원본은
default·look-left·look-right·arms-up 넷뿐이고 전부 입이 없다. 넷만 남기고, 얼마나 다급한지는
**어느 포즈를 얼마나 자주 뽑느냐**로만 말하게 바꿨다. 그림은 하나도 안 늘었는데 두리번거리는
빈도가 올라가고 팔을 드는 비율이 올라간다.

남은 건 카드다. 남의 대화 기록이 아니라 **자기 기록 90일치를 실제로 훑어** 나온 값이라,
이건 다른 데 없다. 약한 걸 버리고 새로운 걸 남겼다.

## 1. 왜 이 모양이 됐나

앤트로픽이 2026-04-01에 낸 `/buddy`가 출발점이다. 계정 해시로 종과 스탯을 뽑아주는
터미널 다마고치였고 2026-04-09 v2.1.97에서 조용히 사라졌다. 복원 요청 이슈는
`not planned`로 닫혔다. 버디가 안 한 것이 둘이다. **자라지 않았고**, 사용 방식과
**아무 상관이 없었다.**

처음에는 Clawd 옆에 세울 새 생물을 만들려 했다. **세 번 그렸고 세 번 다 실패했다.**
앞을 보는 둥근 덩어리에 눈 두 개면 무엇을 붙여도 작은 Clawd로 읽힌다. 꼬리를 달아도,
목을 잘록하게 해도, 옆모습 네발로 종을 바꿔도 "짭 Clawd"라는 인상이 안 없어졌다.

원인은 단순했다. **Clawd의 친구를 그리면 그건 Clawd다.** 그래서 새 생물을 버리고
Clawd 하나를 키우는 쪽으로 틀었다. 여기에 이 판단을 남겨 두는 이유는, 나중에 누가
"옆에 펫 하나 세우면 재밌겠는데"를 다시 떠올릴 것이기 때문이다. 세 번 해봤고 안 된다.

## 2. 먹이와 레벨

**먹이는 토큰이다.** 출력 토큰 + 새로 들어간 입력 + 캐시에 새로 쓴 것.
**캐시 재읽기는 세지 않는다.** 실측에서 그것만 120억이라 넣으면 다른 게 전부 묻힌다.

```
누적 필요 먹이 C(n) = 5,000 × n³ × 요금제계수
```

요금제계수는 **절반 보정**이다. 소비 여력 비의 제곱근을 쓴다.

| 요금제 | 계수 |
|---|---|
| Pro | 0.45 |
| Max 5x | 1.0 |
| Max 20x | 2.0 |
| 그 외·불명 | 1.0 |

높은 요금제가 여전히 빨리 크되 격차가 4배가 아니라 2배로 줄어든다. Pro도 왕관까지 간다.
요금제는 `~/.claude.json`의 `oauthAccount.organizationRateLimitTier`에서 읽는다.

나이는 부화가 아니라 **클로드 코드를 처음 쓴 날**부터 센다(`claudeCodeFirstTokenDate`).
설치가 늦었다고 손해 보지 않는다. 지금은 카드에만 쓰고 해금 조건에는 안 걸었다.

## 3. 스탯

전부 클로드를 어떻게 쓰는지를 잰다. 0–100.

| 스탯 | 재는 것 | 원천 |
|---|---|---|
| APPETITE | 하루에 먹는 토큰 | 활동일당 먹이 중앙값 |
| REACH | 바깥 도구로 손을 뻗는 정도 | MCP·웹 호출 / 전체 도구 호출 |
| STAMINA | 한 대화를 얼마나 오래 끄는가 | 세션당 턴 중앙값 + 세션당 컴팩트 |
| PACK | 서브에이전트를 얼마나 부리는가 | 세션당 sidechain 메시지 |
| NOCTURNE | 밤에 일한 비중 | 22–06시 호출 비중 |

정규화는 `stats.ANCHORS`의 기준점 사이를 선형 보간한다. 기준점은 계정 하나로 뽑은 값이라
남의 환경에서 이상하면 **이 표만 고치면 된다.** 다시 재려면 `tools/`의 스캐너를 쓴다.

하나가 90을 넘으면 칭호가 붙는다. GLUTTON · ROAMER · MARATHON · LEGION · OWL.

## 4. 악세사리를 왜 뺐나

레벨로 모자를, 칭호로 따라다니는 친구를 여는 옷장을 만들어 실제로 돌려봤다.
색을 몸통과 다르게 칠해야 혹이 아니라 걸친 것으로 읽힌다는 것까지 알아냈고, 그건 맞았다.

그래도 뺐다. **한 판 돌려보니 레벨업에 맛이 없었다.** Lv.36에서 37로 가도 아무 일이 없고
다음 모자는 40이다. 65레벨에 7개면 보상이 너무 드물다. 촘촘하게 고쳐도 얹을 수 있는 게
머리 위 색덩어리뿐이라 천장이 낮다.

교훈은 이거다. **캔버스가 못 받쳐주는 보상 체계는 밀도를 늘려도 안 산다.**
9칸 3행에 꾸미기를 얹으려면 캔버스부터 바꿔야 하는데, 그러면 그건 시즌 1이 아니다.

코드는 `git log`의 0.3.0 작업 구간(closet.py)에 남아 있다.

## 5. 구조

훅이 장부를 적고 상태줄은 읽기만 한다. 상태줄이 매초 돌면서 쓰기까지 하면 세션 여러 개가
같은 파일을 동시에 건드리고, 실행 중 다음 갱신이 오면 취소되어 누락이 생긴다.

```
scripts/
├ statusline-clawd.py   Clawd를 그린다. 0.2.0과 같다. 장부를 읽지 않는다
├ growth_cli.py         start · card · json
├ feed.py               훅 진입점. 장부에 쓰는 것은 여기뿐
├ scan.py               대화 기록에서 먹이와 스탯 원자료를 뽑는다
├ stats.py              원자료 → 스탯 다섯
├ grow.py               레벨 곡선과 요금제 계수
└ ledger.py             장부 읽기·쓰기, 원자적 교체와 잠금
```

장부는 `$CLAUDE_CONFIG_DIR/clawd-statusline/state.json`.
플러그인 데이터 폴더가 아니라 설정 폴더에 둔다. **플러그인을 지웠다 다시 깔아도 레벨은 남아야 한다.**

**새 토큰만 세는 법.** Stop 훅이 `transcript_path`를 준다. 세션마다 어디까지 읽었는지
바이트 위치와 마지막 `message.id`를 적어 두고 그 뒤만 파싱한다. 한 번의 호출이 파일에
여러 줄로 저장되므로 id로 묶어야 한 번만 세어진다. 실측에서 4,190줄이 2,394번의 호출이었다.

**상태줄은 장부를 아예 안 읽는다.** 성장을 켜든 말든 Clawd는 0.2.0과 똑같이 그려진다.
카드만 장부를 읽는다.

## 6. 예외

| 상황 | 처리 |
|---|---|
| 기록이 없는 새 계정 | Lv.1로 시작. 첫 세션 뒤 다시 계산 |
| 요금제를 못 읽는다 | 계수 1.0 |
| 대화 기록 보존이 30일 | 그 범위만 본다 |
| 장부가 깨졌다 | 없는 것으로 보고 0.2.0처럼 그린다 |
| 성장을 안 켰다 | 장부가 없다. 카드가 안내만 하고 상태줄은 평소대로 돈다 |

## 7. 실측

2026-09-04, 계정 하나 기준.

| 항목 | 값 |
|---|---|
| 상태줄 1회 실행 | 0.027초 |
| 전수 스캔 (222파일 1.5GB) | 5.4초, 설치할 때 한 번 |
| 44일간 먹이 | 2.4억 토큰 → Lv.36 |
| 컴팩트 | 91회 |
| 세션당 턴 | 중앙값 46, 최대 4,705 |

설계 단계에서 APPETITE를 92로 봤는데 실제로는 75였다. 활동일당 먹이를 중앙값으로 잡으니
가볍게 쓴 날이 값을 끌어내린다. 기준점을 억지로 맞추지 않고 그대로 뒀다.
